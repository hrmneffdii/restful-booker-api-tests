# API-002: POST /booking returns 500 Internal Server Error when a required field is missing

| Field | Details |
|---|---|
| **Severity** | High |
| **Priority** | P2 |
| **Status** | New |
| **Type** | Functional / Input validation |
| **Endpoint** | POST /booking |
| **Reported by** | Herman Effendi |
| **Date reported** | 2026-10-29 |
| **Environment** | https://restful-booker.herokuapp.com, tested with Playwright 1.64.1, Ubuntu 24.04 |
| **Reproducibility** | 5 out of 5 attempts |

## Summary
Sending a booking without a required field (`firstname`, `lastname`, or `bookingdates`) makes the server respond with `500 Internal Server Error`. Invalid input from the client should be rejected with a 4xx status and a helpful message, not cause a server error.

## Preconditions
- The API is reachable.
- No authentication is needed to create a booking.

## Steps to Reproduce
1. Send a POST request to `https://restful-booker.herokuapp.com/booking` with headers `Content-Type: application/json` and `Accept: application/json`.
2. Use a valid booking body but remove the `firstname` field: `{"lastname":"Santoso","totalprice":500,"depositpaid":true,"bookingdates":{"checkin":"2027-01-10","checkout":"2027-01-15"},"additionalneeds":"Breakfast"}`
3. Observe the status code and the response body.
4. Repeat the request with `lastname` removed, then with `bookingdates` removed.
5. (Control) Send the full valid body and confirm that it returns `200` with a booking id.

## Expected Result
A `400 Bad Request` or `422 Unprocessable Entity` response that names the missing field, for each of the three variants.

## Actual Result
Status `500 Internal Server Error` for the variants above. [VERIFY: paste the exact status line and response body for each variant, and note any variant that behaves differently.]

## Evidence
- Automated tests: `tests/known-issues.spec.ts`, "API-002: missing required field firstname / lastname / bookingdates should return a 4xx status" (marked with `test.fail()` while the issue exists).
- Control: `tests/create.spec.ts`, "creates a booking and returns an id" passes with a full body.

## Impact
- **API consumers:** a 500 tells the client that the server failed, not that its request was wrong. Developers cannot tell what to fix, and clients may retry pointlessly.
- **Operations:** invalid requests raise false server-error alerts and hide real failures in error-rate dashboards.
- **Quality and security:** missing input validation means the server does not control what reaches its processing logic. This can hide deeper problems and is a common weakness class.
- **Severity rationale:** High. Input validation is basic API behaviour, and the server fails on a common mistake, although valid usage still works.
- **Priority rationale:** P2. Should be fixed in the next planned release.

## Possible Cause (hypothesis, not confirmed)
Required fields are probably not validated before the data is processed, so an unhandled exception results in a 500. This is a guess from black-box observation only.

## Suggested Fix
Validate the request body against a schema before processing it. Return `400` or `422` with the name of each missing or invalid field. Add regression tests for every required field.

## Workaround
Clients must validate the payload themselves before sending it.
